Give your agent OBS

obs-studio-rust includes a local MCP server that calls libobs directly. It has {{n_tools}} typed tools, with input and output schemas and machine-readable errors. An agent can build scenes, go live, take screenshots and wait on real conditions, without screen-scraping or fixed sleeps.

# 1. build once, inside an obs-studio checkout
git clone https://github.com/obs-rust/obs-studio && cd obs-studio
./mcp --build

# 2. hand it to your agent
claude mcp add obs -- "$PWD/mcp" --mcp

One choice to make

Its own OBS, or yours

--mcp · stdio

Its own OBS

The server starts and owns a separate headless OBS instance. It's a sandbox apart from the OBS you have open, suited to building scenes, tests and CI. Closing stdin shuts it down cleanly.

./mcp --mcp
--mcp-attach · acts on your live app

Your running OBS

Build and install obs-mcp-module. It serves the same JSON-RPC on $XDG_RUNTIME_DIR/obs-studio-rust/control.sock (mode 0600) inside the running app, and the agent's changes go straight to your live scenes.

./mcp --mcp-attach
By annotation

Look, switch, change

Every tool declares MCP annotations, so a client can grant "look, don't touch" by policy. A read-only allowlist is generated for Claude Code.

{{n_ro}}

Read-only

Lists, status, screenshots, stats and waits. Safe to allow outright.

{{n_idem}}

Idempotent writes

Start/stop outputs, switch scenes, toggle visibility. Repeating a call gives the same state.

{{n_mut}}

Changes state

Create, remove and reconfigure scenes, sources and items. Put these behind a human.

Client configs

Plug it in

Every client launches the mcp script in your checkout. It sets up the graphics and plugin paths, so point clients at it rather than at the binary. Use absolute paths.

claude mcp add obs -- /path/to/obs-studio/mcp --mcp

# or just open the checkout: its .mcp.json already declares the server

# optional: allow only read-only tools without prompting (.claude/settings.json)
{"permissions":{"allow":{{ro_allow}}}}

~/.cursor/mcp.json or .cursor/mcp.json

{"mcpServers":{"obs":{"command":"/path/to/obs-studio/mcp","args":["--mcp"]}}}

.vscode/mcp.json in the obs-studio checkout

{"servers":{"obs":{"type":"stdio","command":"${workspaceFolder}/mcp","args":["--mcp"]}}}

The server builds and runs on Linux today (see requirements). Claude Desktop ships for macOS and Windows, so this config only helps where Desktop runs on the same Linux machine as the build.

{"mcpServers":{"obs":{"command":"/path/to/obs-studio/mcp","args":["--mcp"]}}}

Act on a running OBS that has obs-mcp-module loaded. The socket argument is optional and defaults to the module's socket.

{"mcpServers":{"obs-live":{"command":"/path/to/obs-studio/mcp","args":["--mcp-attach"]}}}

Newline-delimited JSON-RPC 2.0 over stdio. No client needed.

printf '%s\n' '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | ./mcp --mcp
Honest requirements

What it needs

Local only

stdio, or a unix socket with mode 0600. No network listener, no hosted endpoint.

Built from source

./mcp --build needs uv, soldr and the native libobs build dependencies. On NixOS the launcher enters ci/mcp-shell.nix itself. No release package includes the server yet.

Linux first

The launcher builds EGL/Wayland OpenGL, linux-v4l2, obs-ffmpeg and obs-x264. The socket transport is unix-only, and Windows named pipes are tracked in #4455. macOS is untested.

A display for video

Video and screenshots need a Wayland compositor or X server; headless Weston works. Control-only use runs with neither. In upstream's words: "A successful tools/list response alone does not prove video or device readiness."

Configured outputs

Record and stream tools use the outputs and service you have configured. No tool configures them yet.

Annotations are advice

Hints describe intent, and your client still enforces policy. Use the allowlist above for read-only agents.
